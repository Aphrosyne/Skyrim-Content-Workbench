# SCW 阶段推进（Stage Workflow）

按 SCW 的 UX 重构路线图推进一个开发阶段。流程分 5 个阶段门，按顺序执行，不得跳步、不得合并。

## 阶段门

### 1. PLAN（计划）

- 判断任务来源：来自当前权威路线图（文件名以 AGENTS.md 的"开发依据"为准；当前为 `docs/ux-redesign-roadmap.md`，仓库另有 `docs/roadmap.md` 主路线图，两者独立，勿混淆）→ 必读对应章节；来自问题清单/独立修复 → roadmap 不默认读取。
- `docs/spec.md`、`docs/architecture.md`、`docs/technical-debt.md`、`docs/PROJECT_HANDOVER.md` 按任务相关性按需阅读，禁止无目的扫描全部文档。
- 先判断任务规模：小修复 → 简短计划；功能开发 → 完整模板；架构调整 → 完整模板 + 风险评估。
- 分析代码遵循"先定位入口文件 → 查看调用链 → 再扩大范围"，不读取无关代码。
- 先分析当前代码状态，**不直接编码**。
- 输出完整实施计划，严格使用 [references/plan-template.md](references/plan-template.md) 的模板。
- 列出需要用户确认的问题清单；若发现设计问题，先提出问题并等待确认。
- **等待用户确认计划后再进入编码。**

### 2. CODE（编码）

- 按已确认的计划实施，每次改动小而可审查。
- 不进行无关重构，不改变已有功能行为；每一步保持可运行、可回滚。

### 3. VERIFY（验证）

- 使用 `scw-verify-finish` 的验证步骤：`ruff check`、`ruff format --check`、`pytest`。
- 任一失败先修复并重跑，直到全部通过。

### 4. ACCEPT（验收）

- 将改动摘要与测试结果交给用户手动验收。
- 验收不通过：回到 CODE 修复，循环直至通过。

### 5. FINISH（收尾）

- 使用 `scw-verify-finish` 完成提交与推送。
- 完成后基于 roadmap 生成下一阶段计划；若路线图无下一阶段，说明当前终点并结束。

## 硬性规则

- 用户确认计划前，禁止编码与文件写操作。
- 遵循仓库 AGENTS.md 的不可违反规则（真实文件系统为唯一事实来源、文件操作须用户确认等）。
