### 数据库问题1 ✅ 已修复（v0.50.1，2026-08-02）
- 重命名会在数据库中留存原本的条目？
- 我将一个文件AAA改成了BAA，搜索AA还是能搜到两个文件？
- 移动完成之后又多出一条搜索内容
- GC是否会接管及时清理？
- 我在重启两次后继续搜索，依旧是多条内容
- 优先级L3
- 根因（2026-08-02 已复现确认）：
  - 文件重命名/移动时，FileOperationService 只更新父目录 mtime，不更新
    content_unit 行（只有目录才会重写路径前缀）
  - 扫描持久化只插入新候选、从不删除失效行 → 旧路径残留 + 新路径新增一行；
    搜索匹配 title/notes/标签（title 默认=文件名），两行都命中 → 重复结果
  - 启动 GC 只清理孤立缩略图缓存，不碰 content_unit，重启无效
- 修复方案（用户确认 2026-08-02，已实现并验收）：
  - A：文件重命名/移动原地更新 content_unit 行（path/path_key + 默认标题跟随，
    用户自定义标题保留）
  - B：扫描时清理当前 root 下文件已不存在的 content_unit 行（直接删除，
    级联 content_unit_tag / thumbnail_cache；root 本身不存在时跳过整轮，防误删）
- 保守方案（备用，未启用）：删除前先生成待确认清单，用户确认后再删，
  避免误删仍带标签/备注/封面元数据的行；若后续发现直接删有误删案例再启用

### Bug紧急修复2 ✅ 已修复（v0.50.1，2026-08-02）
- 批量移动内容时（包含文件文件夹），会有些提示移动失败，但是真实内容成功移动
提示：
```
移动到...

部分移动失败：成功11项，失败1项
移动失败：同步 folder_cache失败：无法删除 FolderCache:FOREIGN KEY
constraint failed

```
- 导致移动失败的内容，失去内容单元标记
- 和BugFix1关联
- 优先级L99
- 根因（2026-08-02 已复现确认，直接原因与数据库问题1 修复无关，为既有缺陷）：
  - on_folder_moved 只"删除旧单行 + 插入新单行"；被移动目录在 folder_cache 有
    子目录行（parent_id 引用）时，删除父行触发 FOREIGN KEY constraint failed
    （删除路径早有 delete_folder_subtree 先子后父，唯独移动路径没有）
  - 磁盘已移动但 DB 同步回滚 → 库仍指向旧路径 → 数据库问题1 的 Fix B 扫描清理
    把旧路径 content_unit 行当失效删除 → 文件夹标记（含标签/备注/封面）丢失；
    Fix B 之前这些行只是隐形残留，所以该症状是 Fix B 暴露出来的
- 修复方案（用户确认 2026-08-02，已实现并验收）：
  - on_folder_moved 改为整棵子树迁移（_move_folder_subtree）：新路径行父先子后
    插入（前缀重写、父链重建），旧行先子后父删除，不再 FK 失败
- 后续可选方案（Fix3，已记录 2026-08-02，暂未实施，可能后续增加）：
  - FileOperationService.move 同步失败时尝试把磁盘目标移回源位置（仅限移动前
    目标不存在、非覆盖场景，覆盖无法恢复）；回滚失败则错误信息明确"文件已实际
    移动但数据库未同步"，避免"提示失败但实际移动"后下次扫描清理丢元数据
